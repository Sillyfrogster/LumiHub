# Contributors

## Pull requests are closed

Illarin does not accept pull requests from outside the maintainer and developer
group listed below. A pull request from anyone else is closed without review,
whatever it contains. That is not a judgement on the work. The project is small
enough that one group holds the whole design in its head, and a narrow merge
path is how it stays that way.

Illarin is licensed under the [Apache License 2.0](LICENSE). You may read it,
fork it, change it, and ship your changes, and you do not need our permission to
do any of that. What you cannot do is take it through this repository: the fork
is yours to run, and this tree stays with the maintainers.

## Issues are open to everyone

Anyone can open an issue. No invitation, no prior contribution, no account
standing required. All of these are welcome:

- A typo, a broken link, or wording that reads wrong.
- A bug, a page that fails to load, a result that looks incorrect.
- A feature you want, or a change to one that already exists.
- A question about how something is meant to work.

A clear issue is worth more to this project than a patch it cannot merge. If you
are unsure whether something counts, open it anyway.

Start at the [issue tracker](https://github.com/Sillyfrogster/Illarin/issues).
Pick the template that fits, or open a blank issue if none of them do.

If you paste code into an issue, you are offering it under the Apache License
2.0, the same license as the rest of Illarin.

### What helps

Say what you did, what happened, and what you expected instead. Name the page or
the part of the site. Add a screenshot when the problem is visual. Say which
browser you were using if the problem is in the interface.

### What to leave out

Do not put account passwords, session tokens, or anyone else's personal details
in an issue. Issues are public and stay public.

## Security

Do not report a security problem in a public issue. [SECURITY.md](SECURITY.md)
says where to send it and what to include.
